# `figures/` — the code that draws the article's figures

Everything the manuscript's figures are made from lives here and is version
controlled with the software, so a reader who clones or downloads this
repository can rebuild every figure in the paper.

This closes three audit findings:

| finding | what it said | what this directory does about it |
| --- | --- | --- |
| ISSUE-053 / F-06-5 | the cover letter called the plotting scripts "editorial artifacts … not in the software repository"; MBE's publication condition requires the material underlying the article to be public | the scripts are repository content, released under the same MIT licence and archived under the same Zenodo record as the software |
| ISSUE-058 / F-07-3 | the figures and all plotting scripts were entirely outside version control while Supplementary Note S6 claimed a four-part deliverable | the whole figure pipeline is inside the only git repository of the project |
| ISSUE-062 / F-07-4 | rebuilding depended on repo-external sibling paths, a `node_modules` symlink pointing out of the repo, and a gitignored `_build/` that no longer existed | every path resolves inside the repository; the Fig. 2 inputs are **generated by a documented command** instead of being a hidden prerequisite |

## What is here

| file | role |
| --- | --- |
| `PhyloRecViewer-手稿正文-图1-6.py` | hand-authors the five SVG-carried main figures (Figs. 1, 3, 4, 5, 6) and emits their machine-generated alt text |
| `PhyloRecViewer-手稿正文-图2.py` | assembles Fig. 2 from real application output (panels, measured insets, statistics card, glyph key) |
| `PhyloRecViewer-手稿正文-图2.ts` | the app-side print export: pushes the bundled `9999.nhx.xml` through the application's own parser → layout → `Scene` → `renderToStaticMarkup`, and writes the two measured inputs Fig. 2 consumes |
| `PhyloRecViewer-手稿附件-附图1.py` | Supplementary Fig. S1 — capability matrix and measured scaling, from the frozen aggregate CSVs in `../data/` |
| `phylorec_style.py` | the single shared token module: page width, type floor, line weights, colours, and the TIFF master |
| `svg_raster.py` | rasterises a crop of a vector source through `rsvg-convert` so an inset is a magnification of the drawing, not of a bitmap |
| `export.sh` | renders each SVG-carried figure to its three delivery carriers |
| `compress_carriers.py` | recompresses an already-written TIFF carrier losslessly, from its own pixels (front end for `phylorec_style.compress_tiff_in_place`) |
| `check_figures.py` | the delivery gate: framing, raster dpi, carrier agreement, font embedding, Type3, trim clearance, placed-raster dpi, colour space, glyph coverage, text overlap, rasterised-label floor, TIFF master |

## Rebuilding everything from a clean clone

```bash
git clone <repository> && cd PhyloRecViewer-项目代码
npm install                      # react/react-dom + vite-node, for step 1

# 1. Fig. 2's measured inputs — the application's own render path
PR_OUT=figure2-app-print.svg PR_GENE_THICKNESS=9 PR_SYMBOL_SIZE=18 \
PR_SPECIES_FILL='#e9e9ee' PR_SPECIES_STROKE='#d9d9e0' \
  node node_modules/vite-node/vite-node.mjs figures/PhyloRecViewer-手稿正文-图2.ts

# 2. the five SVG-carried main figures, then their carriers
python3 figures/PhyloRecViewer-手稿正文-图1-6.py
./figures/export.sh                        # or: bash figures/export.sh

# 3. the two matplotlib-carried figures (they write their own carriers)
python3 figures/PhyloRecViewer-手稿正文-图2.py
python3 figures/PhyloRecViewer-手稿附件-附图1.py

# 4. the gate
python3 figures/check_figures.py
```

Steps 2–4 need only Python 3 with the packages listed below; step 1 needs Node.
Steps 2 and 3 are independent of each other and of step 1 except for Fig. 2.

## Where things go, and how to redirect them

Every path is derived from the script's own location, so the pipeline runs from
any working directory and never reads or writes outside the repository. There is
no sibling-directory assumption and no out-of-repo symlink.

| what | default | override |
| --- | --- | --- |
| figure carriers (SVG/PNG/PDF/TIFF) | `figures/` | `PR_FIG_OUT` |
| Fig. 2 measured inputs | `figures/_build/` | `PR_BUILD_DIR` |
| alt-text reports (generated by the scripts) | `figures/_build/alt_text*/` | `PR_ALT_DIR`, `PR_ALT_MD` |
| frozen measurement CSVs | `../data/` (repository content) | `PR_DATA_DIR` |
| interpreter used by `export.sh` | first `python3` on `PATH` that has Pillow + CairoSVG | `PYTHON` |

`figures/_build/` and the carriers are **generated artefacts**; the repository
tracks the code that produces them, not their bytes. `_build/` is covered by the
repository's existing `.gitignore`.

### The `_build/` inputs Fig. 2 reads

`PhyloRecViewer-手稿正文-图2.py` needs `figure2-app-print.svg` and
`figure2-stats.json`. These are not committed and are not a hidden prerequisite:
step 1 above generates both by running the shipped application source over the
fixture `src/parser/__fixtures__/9999.nhx.xml`. Verified on 2026-10-08: the
command reproduced the two files used for the submitted figures **byte for byte**
(`figure2-app-print.svg` 51,746 B, `figure2-stats.json` 203 B, identical MD5).
A third file, `figure2-typography.json`, is an *output* of the Fig. 2 script, not
an input: it records the measured type geometry so the legend and the checker
quote one source of truth.

If the files are absent the script aborts and prints the exact command above
rather than searching for them somewhere else.

## Carriers, and why the TIFF is compressed

MBE's accepted bitmap list is `.tif .eps .ppt .xls .doc .pdf .gif .jpg` and does
not include PNG, so each figure also gets a 1,200-dpi TIFF master. A
stored-*uncompressed* one is 95–260 MB per figure, which is not a carrier anyone
can upload. `phylorec_style.png_to_tiff()` therefore tries each lossless TIFF
codec (Deflate, Adobe-Deflate, LZW), decodes the result, and accepts only the
smallest encoding whose pixels are **exactly** the source pixels and whose
recorded dpi survives the round trip; if none qualifies it writes the
uncompressed file rather than a lossy one. Measured on the seven delivered
masters: 54–261 MB of stored pixels become 0.7–4.3 MB (1.3–1.7 %), pixel-for-
pixel identical — Fig. 2 goes 260.9 MB → 4.3 MB, Fig. S1 95.6 MB → 1.6 MB. Both
`export.sh` and `phylorec_style.save()` use this one code path, so a clean clone
produces shippable carriers by default.

## Toolchain these figures were produced with

Python 3.11.15 · matplotlib 3.11.0 · numpy 2.4.6 · scipy 1.17.1 · Pillow 12.2.0 ·
CairoSVG 2.9.0 · PyMuPDF 1.27.2.2 · fontTools 4.63.0 · librsvg `rsvg-convert`
2.63.2 · Node 20.20.2 · vite-node 2.1.9 (a `vitest` dependency) · react /
react-dom 18.3.1 · vite 5.4.21. The rendered pixels depend on matplotlib and
librsvg; a different matplotlib minor version can change PDF font-subset bytes
without changing the text, sizes, positions or page geometry.

## Known state of the gate

`check_figures.py` is deliberately strict and reports per figure. As of this
revision it fails five assertions — a `≥` glyph missing from an embedded
Helvetica Neue subset (Figs. 1 and 4) and three two-text-box overlaps (Figs. 1,
3 and 6). These are content defects of the figures themselves and reproduce
identically from the pre-existing figure directory: the repository copy changes
no verdict. They are tracked as figure findings, not softened here.
